```text
robin gui [flags] [user@]host [-- ssh-args...]
robin version
```

`robin gui` is the whole interface. Flags go before the destination, and everything after `--` is handed to `ssh` as it is:

```sh
robin gui alice@build-box
robin gui build-box -- -p 2222 -i ~/.ssh/other_key
robin gui --max-size 2560x1440 --fps 60 workstation
robin gui --no-browser lab-node
robin gui --attach auto workstation
robin gui --attach wayland workstation
```

[Flags](/flags) lists every flag with its default.

## SSH

Robin runs your own `ssh` binary (`--ssh` picks another one) and opens a single ControlMaster connection with `ssh -M`. The probe, the agent upload, the agent itself and the media tunnel all ride that one connection, so you authenticate once. `~/.ssh/config` with `Match` and `Include`, `ProxyJump`, `ProxyCommand`, the SSH agent, FIDO keys, certificates, Kerberos and interactive prompts for passwords, 2FA or an unknown host key all work the way they do for `ssh` on its own.

If that SSH connection drops, the session ends; sessions that survive a drop are on the [Roadmap](/roadmap).

## Spawning a desktop

Without `--attach`, the agent starts its own display. It runs Xvfb on a free display number at `--max-size`, then switches RandR modes so the display matches your browser window, up to that size. Inside it goes the lightest session the agent finds: Xfce if `xfce4-session` is installed, else a window manager (openbox, fluxbox, icewm or twm) with a terminal beside it, else a bare terminal. `--session` runs a command of your choosing instead:

```sh
robin gui --session startxfce4 build-box
```

The session gets a sensible locale even when SSH brought none. The agent keeps any `LANG`, `LC_ALL` or `LC_CTYPE` it was given, else reads `LANG` from `/etc/locale.conf` or `/etc/default/locale`, and falls back to `C.UTF-8`, so a terminal does not end up in the C locale drawing UTF-8 prompts as mojibake.

## Attaching to a running desktop

`--attach` streams a desktop that already exists instead of starting one. `auto` picks your active session, Wayland or X11; `:1` names an X display; `wayland` goes through the desktop's screen sharing portal. An attached desktop is shared with whoever sits at the machine, and it keeps its own resolution, so the browser scales the picture rather than resizing the remote screen. The details differ enough to have their own pages: [Attaching to X11](/attach-x11) and [Attaching to Wayland](/attach-wayland).

## Size, frame rate and HiDPI

`--max-size` is the largest remote resolution, 1920x1080 by default and 1280x720 on hosts with two cores or fewer. A spawned display follows your window up to it. An attached desktop larger than it, a 4K monitor say, is scaled down to fit, and the pointer is mapped back onto the full-size screen. The downscale averages the exact source area under each output pixel, since plain sampling drops strokes of text.

`--fps` caps the frame rate: 30 by default, 20 on small hosts. Below the cap, frames go out only when the screen changes, so the status tab reads 0 fps on an idle screen, which is not a stall.

`--hidpi` sizes a spawned display in your browser's device pixels instead of CSS pixels. On a Retina screen that gives sharp text at about four times the pixels to encode. Raise `--max-size` with it if you want the display fully native.

<Callout type="note" title="When the picture looks soft or blocky.">
Two things are worth checking today. An attached monitor larger than `--max-size` is scaled down, and the default is 1920x1080, so a 2560x1440 monitor arrives shrunk; `--max-size 2560x1440` sends it at its own size, at the cost of more pixels to encode. On a Retina or other HiDPI client screen, a spawned desktop renders in device pixels with `--hidpi` and a raised `--max-size`. Text that stays soft once the screen is still is what [sharp text](#sharp-text-and-actual-size) is for. Blockiness while the screen is changing, when the link's estimate dips, is a known weak spot with planned work: see [crisp video in motion](/roadmap#crisp-video-in-motion) on the Roadmap.
</Callout>

## Sharp text and actual size

H.264 as browsers decode it keeps colour at a quarter of the picture's resolution, which smears coloured text and softens the rest, and a picture the browser scales by a fraction blurs it again. The status tab has a switch for each.

**Sharp text**, on by default, sends the parts of the screen that have been still for 300 ms again without loss: 64x64 tiles, compressed to PNG on the host within a quarter of one core and drawn on a layer over the video, at the desktop's own resolution even where the video is scaled down to `--max-size`. A tile goes the moment its part of the screen changes, before the frame that changes it shows, so what moves is plain video and text you stop at sharpens about half a second later. A screen full of small text costs about 700 KB once at 2560x1440, and nothing more while it stays still. A tile that keeps changing soon after it was sent, as one with a blinking caret does, soon stays video rather than flicker. Sharp text needs an X11 desktop and a browser that says which frame it shows (Chrome, Edge and Firefox do); otherwise the switch is off and says why.

**Actual size** shows one desktop pixel to one pixel of your screen instead of fitting the picture to the window, so text never goes through a fractional scale. A desktop larger than the window pans: hold the pointer near an edge of the window, or on a touch screen move two fingers apart and along.

## Monitors

An attached X11 desktop with several monitors shows one of them at a time, starting with the primary one. `--monitor` picks another by name (`--monitor DP-2`), by its number in `xrandr --listmonitors` order (`--monitor 2`), or `all` for every monitor in one picture. While you are connected, the status tab lists the monitors with their sizes and switches between them. A Wayland desktop shows the monitor picked in its own sharing dialog. More on this under [Attaching to X11](/attach-x11#monitors).

## Bitrate and transports

`--max-kbps` is the video bitrate ceiling, 10000 kbit/s by default. Congestion control works below it, following what the link actually carries, so raising the ceiling only helps on a link with room to spare.

`--transport` picks the media path:

- `auto`, the default, offers both direct UDP and the SSH tunnel and lets ICE choose. UDP wins whenever it works. If UDP stops mid-session, the page notices and moves onto the tunnel in about three seconds.
- `direct` offers UDP only.
- `tunnel` forces the SSH path. With `tunnel` the session fails if the SSH forward cannot be opened; with `auto` it carries on over UDP alone and logs a warning.

`--stun` sets the STUN servers used to find a public address for NAT traversal, comma-separated. The default is Google's public server, `stun:stun.l.google.com:19302`, and `none` turns STUN off. How the paths fit together is on [How it works](/how-it-works#transports-and-fallback).

## Encoders and sound

`--encoder auto`, the default, encodes on the host's GPU where the probe shows that it pays and in software everywhere else; `software`, `vaapi` and `nvenc` insist on one, and a GPU encoder you name fails the session if it cannot run. See [Hardware encoding](/hardware-encoding).

Sound comes along by default from the spawned session's private sound server or from the attached desktop's own. `--audio=false` leaves it out. See [Sound](/sound).

## The page

The page runs on `127.0.0.1` on a random port (`--listen` sets the address; anything that is not a literal loopback IP, `localhost` included, is refused) and needs the token in the link the CLI opened or printed. The status tab hanging from the top edge shows:

- the state: Connecting, Connected, Reconnecting or Session ended
- the transport, **Direct UDP** or **SSH tunnel**
- the picture's resolution, frame rate and bitrate
- a monitor menu, on attached X11 desktops with more than one monitor
- the speaker toggle, once an audio track arrives, and the full screen button

The tab tucks itself away while things are healthy and comes back when the pointer nears the top of the window.

Full screen also requests keyboard lock, which lets shortcuts like Ctrl+W and Alt+Tab reach the remote desktop instead of the browser where the browser supports it; without it the session works the same, minus those keys.

Only one browser holds a session at a time. A second tab is refused, with a note to use the most recent link, until the first one closes; reloading the tab you already have is fine, and so is closing it and opening the link again.

### Keyboard, pointer and clipboard

Keys are sent by character. The agent finds the key and shift level that produce each character on the remote keymap, and on X11 binds a spare keycode when the keymap lacks one, so text arrives right whatever your local layout. Named keys such as Enter, arrows, function keys and modifiers are held until you release them. On a Mac, Cmd is sent as Control. IME composition, as used for CJK input, is not forwarded.

The clipboard carries plain text, up to 255 KiB in each direction. Your paste shortcut in the page sends the local clipboard to the remote before the key itself, so the remote program pastes what you just copied. Text copied on the remote is written to your local clipboard when the page has focus and permission.
