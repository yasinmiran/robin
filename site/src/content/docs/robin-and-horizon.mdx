Horizon is a virtual desktop infrastructure (VDI) platform. An organization runs it to deliver desktops to its users. Robin is one command between you and a Linux box you can already ssh to. Comparing the two is useful mostly because the remote desktop experience is where they meet, and much of Robin's recent work was chosen by looking at where Horizon's experience was ahead.

## Different shapes

Robin has no server of its own. There is nothing of Robin's to install on the host beforehand (a spawned desktop still needs Xvfb and a window manager), no broker that hands out desktops, no gateway, and no port opened for authentication; the agent is copied over SSH when you connect, runs as your user, and when the session ends it stops everything it started and removes its run directory. Who may use a machine is decided by who may log in to it over SSH, and the SSH setup you already have (jump hosts, keys, certificates, 2FA) is the whole access story.

That shape is the reason for most of what Robin does not do. With no central service there is nothing to pool desktops or assign them to users, and none of that is coming.

## What overlaps

On the experience of using one remote desktop, Robin covers it in a browser, without a client install beyond the `robin` binary:

- picture, keyboard and pointer, with keys mapped by character so any client layout types the right text, input methods and touch included
- a clipboard of text, HTML and images both ways, up to 16 MiB, and files both ways
- sound from the remote desktop, Opus with forward error correction for speech, and your microphone and camera offered to the host's programs
- a desktop that outlives the connection and that `robin gui` picks up again
- a spawned desktop that follows the browser window's size, and an attached desktop with a monitor picker
- congestion control that follows the link, sharp text over still parts of the screen, and H.264 on the host's GPU where that pays
- direct UDP when the network allows it, the SSH connection when it does not, and failover between them mid-session
- attaching to the desktop you are logged in to, on X11 or on GNOME and KDE Plasma under Wayland, with consent at the screen, and keeping its own screen dark and speakers quiet while you work

## The gaps, closed and open

These are the gaps against Horizon judged worth closing, plus one for picture quality while the screen changes. The [Roadmap](/roadmap) describes each.

### Closed

| Feature | What Robin does |
|---|---|
| [Reconnectable sessions](/sessions) | the desktop outlives the connection and `robin gui` resumes it |
| [Microphone and camera](/microphone-and-camera) | the browser's devices appear as devices on the host |
| [Files](/files-and-clipboard) | upload by dropping on the page, download on a click |
| [Rich clipboard](/files-and-clipboard#the-clipboard) | text, HTML and PNG images, up to 16 MiB |
| [Sharp text](/using#sharp-text-and-actual-size) | lossless tiles over regions that have gone still, and an actual-size view |
| [Private sessions](/private-session) | curtain the host's own screen and silence its speakers |
| [More clients](/browsers) | IME, touch, Windows and Android, beside macOS and Linux |
| [Crisp video in motion](/how-it-works#video-in-motion) | measured tuning of keyframes, pacing and rate control |

### Open

| Feature | What comes next |
|---|---|

## What Robin does not aim to be

Robin stays a tool for machines you can already reach. Running desktops for an organization, from provisioning them to brokering who gets which, is what a VDI platform is for, and Robin adds none of it. iOS also stays out, since there is no way to run the CLI there, which leaves the clients at macOS, Linux, Windows and Android.
